# Music Love — бесплатное облачное размещение

Архитектура без локального диска:

- **Netlify** — Next.js, страницы и API.
- **Turso Cloud (libSQL)** — существующая SQLite/libSQL-база.
- **Supabase Storage** — обложки, треки, аватары, отчёты и вложения.

Интерфейс не меняется. Файлы загружаются из браузера напрямую в Supabase через
короткие подписанные URL, поэтому ограничение Netlify на тело запроса не мешает
загрузке аудио. Приватные отчёты и вложения открываются только после проверки
сессии, затем `/api/files/...` выдаёт короткую подписанную ссылку на скачивание.

## Бесплатные ограничения

- Netlify Free: месячный лимит кредитов; при его исчерпании проект может быть
  приостановлен до следующего периода. Плата за превышение не списывается.
- Turso Free: облачные лимиты на строки и хранение; при исчерпании запросы могут
  блокироваться до следующего периода.
- Supabase Free: 1 GB файлов, максимум 50 MB на файл; проект может быть
  приостановлен после недели неактивности. Для восстановления потребуется действие
  в панели Supabase.

Эти ограничения нельзя считать гарантией постоянной доступности. Для коммерческой
нагрузки и больших аудиоархивов понадобится платное увеличение ресурсов или VPS.

## Переменные окружения Netlify

Пример находится в `deploy/netlify.env.example`. Значения задаются только в
Netlify UI/CLI и не добавляются в GitHub. `NEXT_PUBLIC_*` — публичные значения;
`JWT_SECRET`, `TURSO_AUTH_TOKEN` и `SUPABASE_SERVICE_ROLE_KEY` — секреты.

`NEXT_PUBLIC_STORAGE_DRIVER=supabase-direct` обязан быть установлен **во время
сборки**, иначе браузерный код продолжит использовать старые multipart-endpoint'ы.

## Перенос базы

Создайте именно **libSQL**-базу Turso (без флага `--tursodb`). Новая удалённая база
должна быть пустой. Скрипт откажется перезаписывать базу, если в ней уже есть
таблицы.

```bash
LOCAL_DATABASE_URL=file:/absolute/path/music-love.db \
TURSO_CONNECTION_URL=libsql://YOUR_DB.turso.io \
TURSO_AUTH_TOKEN=YOUR_TOKEN \
npm run migrate:turso
```

Скрипт создаёт схему, копирует строки с учётом зависимостей внешних ключей,
проверяет `foreign_key_check` и совпадение количества строк во всех таблицах.

## Перенос файлов

```bash
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co \
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY \
LOCAL_STORAGE_DIR=/absolute/path/storage \
npm run storage:supabase
```

Скрипт создаёт/обновляет buckets и загружает существующие файлы с теми же ключами.
`reports` и `ticket-attachments` остаются приватными; остальные buckets публичные.
Для настройки без копирования файлов добавьте `-- --setup-only`.

## Приёмка

1. Главная и `/api/health` открываются по HTTPS из нескольких внешних сетей.
2. Вход/выход администратора и артиста, обновление страницы с сохранением сессии.
3. Старые обложки и треки открываются; HEAD и Range возвращают корректный ответ
   после перехода по подписанной/CDN-ссылке.
4. Загрузка новой обложки и трека больше 4,5 MB происходит напрямую в Supabase.
5. Аватар обновляется после прямой загрузки и записи в Turso.
6. Приватные вложения и отчёты недоступны без сессии и чужому артисту.
7. Данные и файлы остаются после повторного production deploy.

Перед переключением пользователей нужна отдельная резервная копия SQLite и всех
файлов. SMTP по-прежнему необходим для кодов новой регистрации.
