# Music Love — GitHub + Render с постоянным диском

Эта схема сохраняет текущий Next.js-сайт, SQLite/libSQL-базу и локальные файлы.
GitHub хранит только исходный код. Сам сайт выполняется на Render; GitHub Pages
для этой полноценной версии не подходит.

## Почему нужен платный сервер

Бесплатные web-сервисы Render не поддерживают постоянные диски. Без диска SQLite
и загруженные файлы теряются при перезапуске или повторном развертывании.
В `render.yaml` уже указаны платный сервер `1c-2g`, регион Frankfurt и диск 10 GB.
Точную стоимость необходимо проверить в Render до подтверждения создания сервиса.
Диск можно увеличить позже, но нельзя уменьшить через Blueprint.

## 1. Приватный репозиторий GitHub

Создайте пустой приватный репозиторий без README, затем из каталога проекта:

```bash
git remote add origin git@github.com:YOUR_LOGIN/music-love.git
git push -u origin main
```

Не добавляйте в репозиторий `.env`, SQLite-файлы, резервные копии или каталог
загрузок. Они исключены через `.gitignore`.

## 2. Создание сервиса

1. В Render выберите **New → Blueprint**.
2. Подключите GitHub и выберите репозиторий Music Love.
3. Render обнаружит `render.yaml` в корне.
4. Проверьте сервер `1c-2g`, регион Frankfurt, постоянный диск 10 GB и стоимость.
5. Подтвердите создание и дождитесь первого развертывания.

Render назначит HTTPS-адрес вида `https://…onrender.com`. После первого запуска
добавьте в переменные окружения:

```text
NEXT_PUBLIC_APP_URL=https://ВАШ-СЕРВИС.onrender.com
```

Для писем с кодами регистрации также нужны реальные `MAIL_HOST`, `MAIL_PORT`,
`MAIL_USER`, `MAIL_PASS`, `MAIL_FROM`. Не помещайте их в GitHub.

## 3. Перенос существующей базы и файлов

Эти данные не должны публиковаться в GitHub. Их следует перенести отдельно через
SSH/SFTP после настройки SSH-доступа Render.

Примеры (замените имя сервиса и регион на значения из Render Shell):

```bash
# Загрузить согласованную копию базы под временным именем
scp -s ./music-love.db YOUR_SERVICE@ssh.YOUR_REGION.render.com:/var/data/music-love.db.import

# Загрузить существующие файлы
scp -s -r ./storage YOUR_SERVICE@ssh.YOUR_REGION.render.com:/var/data/
```

Затем в Render Shell:

```bash
mv -f /var/data/music-love.db.import /var/data/music-love.db
mkdir -p /var/data/storage
```

После замены базы перезапустите сервис через Render Dashboard, чтобы приложение
открыло новый файл. Не удаляйте диск и не создавайте новый сервис для обновлений.

## 4. Приёмка

Проверить на публичном HTTPS-адресе:

1. `/api/health` возвращает `{"ok":true,"service":"Music Love"}`.
2. Открываются главная страница, стили и клиентские скрипты.
3. Вход администратора и Kurmur, выход и повторный вход.
4. Панель администратора и кабинет артиста.
5. Загрузка обложки и трека, последующее скачивание и Range-запрос.
6. База и новые файлы остаются после ручного перезапуска сервиса.
7. Новая регистрация — только после настройки SMTP.

## Обновления и резервные копии

Изменения в ветке `main` могут развертываться из GitHub автоматически. Сервис с
постоянным диском имеет краткий простой во время замены версии. Перед обновлением
нужна резервная копия базы и файлов; копии следует хранить также вне Render.
